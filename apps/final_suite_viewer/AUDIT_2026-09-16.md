# Final-suite viewer independent audit — 2026-09-16

Branch: `audit/final-suite-viewer-2026-09-16`

## Overall assessment

The viewer architecture is appropriate for the fixed 70-task final suite: catalogue-driven navigation, cached file-only loading, no checkpoint replay, saved-diagnostic PDE inspection, explicit observation likelihood diagnostics, paired noise analysis, and dedicated inverse-parameter views are all consistent with the final-suite design.

It is **not yet possible to give unconditional scientific acceptance on the final HPC suite from the repository checkout alone**. Two required validation inputs are not repository-tracked:

1. a canonical full time × species × weight mizer truth state; and
2. the multispecies final-suite run output directories.

The application correctly refuses to substitute task 13 or observation `value_true` for latent-state truth. Real-output smoke tests and independent plotted-value spot checks therefore remain blocked until those outputs are copied locally.

## Source-of-truth findings

- Final suite: `scripts/final_model_suite.slurm`, tasks 0–69. Catalogue mapping matches the script, including paired noise seeds, no gap-20–30 task, PINN/NN pairings, Rmax/CV/effort starts, and gate-OFF rep1-only controls.
- PDE: `R_log = dlogN_dt + g*dlogN_dw + mu + dg_dw`. The minus-sign form in the audit request is not the repository implementation. Network derivatives are converted from scaled coordinates to physical `t,w` before the residual is assembled and before fixed-grid fields are saved.
- Observation residual: `r = log(y + eps) - log(yhat + eps)`, `eps=1e-30` in the final suite; `sigma_log=sqrt(log(1+CV^2))`; `z=r/sigma_log`; per-observation NLL is `0.5*z^2 + log(sigma_log)` up to the omitted constant.
- Discrepancy gate: `Q=sum(z^2)` and data loss is active only when `Q > chi2_0.95(n)` when the gate is enabled.
- Catch intervals: final suite sets three quadrature points; catch uses the left-closed points `t_start`, `t_start+Δt/3`, `t_start+2Δt/3` and multiplies the mean instantaneous catch rate by `|Δt|`.
- Fishing mortality: `F[g,i](t,w)=E[g](t) q[g,i] s[g,i](w)` with physical-time linear effort interpolation in the model operator.

## Correctness fixes made

1. **Half-open missing-data gaps.** `gap_mask()` now uses `[start,end)`, matching `final_runs/make_data.R`. Year 20 is observed in the 10–20 experiment and year 40 is observed in the 30–40 experiment.
2. **Biological active-size bounds.** `load_w_max()` no longer infers `w_max` from PINN prediction support. It resolves only explicit `w_max.csv` model input and additionally resolves project-relative configured input directories. Inferring biological support from a shared PINN evaluation grid could include inactive species bins.
3. **Regression tests.** Updated missing-gap expected values and added a test proving `w_max` is not inferred from prediction support.

## Performance/UI audit

The application is file-only. Discovery, CSV/JSON loads, truth loads, alignments, observation designs and run metrics use Streamlit data caching. Ordinary species/time/body-weight controls filter cached DataFrames. The viewer does not load a checkpoint, run a neural-network forward pass, invoke autograd, or evaluate the PDE while interacting.

A full browser-level Streamlit smoke test was not possible in the audit execution environment because Streamlit is not installed there and the final HPC output directories are not available. Source inspection confirms controls are selectors/sliders rather than routine typed numeric inputs and page state is session-backed.

## Parking lot — outside viewer scope

1. Formal residual-on-mizer-trajectory validation remains a model-validation task (`docs/ai_context/07_KNOWN_ISSUES.md`).
2. Resolve the continuous predation-kernel support convention against mizer before treating residual quality as proof of biological equivalence.
3. If future runs need full per-term weighting gradients or full causal chunk vectors in the viewer, save those diagnostics during training; do not reconstruct them from checkpoints.
